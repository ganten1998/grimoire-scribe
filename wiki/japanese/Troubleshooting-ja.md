# 困ったときは

## 既知の問題

- **ファームウェア 5.20.1 で KOReader の最初の画面が不完全になることがあります。** KOReader は
  最初の画面を一部欠けた状態で描くことがあり、Grimoire から戻ったときにも起こります。これは
  KOReader の問題（[koreader issue 16283](https://github.com/koreader/koreader/issues/16283)）
  であり、Grimoire は修正しません。

## すぐに試せる対処

- **動かなくなったら** 電源ボタンを 4 秒長押しします。Grimoire がページを保存して閉じ、Kindle の
  画面に戻ります。それでも何も起きない場合は、Kindle が再起動するまで（約 40 秒）長押しして
  ください。再起動してもノートは残ります。パスコードのリセットコード 111222777 は絶対に使わないで
  ください。Kindle が消去され、ノートも失われます。
- **再起動後に Kindle のパスコードがオフになっている**: Grimoire を開いたまま Kindle が再起動
  しました（`grimoire.log` に記録があります）。Kindle の設定（デバイスオプション > デバイスの
  パスコード）でパスコードをオンに戻してください。Grimoire はそこには関与しません。
- **「このページは新しいバージョンで作られています。読み取り専用で表示されます。」**: そのページを
  変更するには Grimoire を更新してください。ページの内容は失われません（「バージョン間の移動」を
  参照）。
- **KOReader**: Grimoire は KOReader の **Tools > Grimoire** から開いてください。
  *シェルスクリプトを実行* は使わないでください（[KOReader](KOReader-ja) を参照）。ライブラリで
  Grimoire をタップした後に「Grimoire は起動しませんでした: KOReader が実行中です。」と画面上部に
  表示される場合は、KOReader がバックグラウンドでまだ動いています（クラッシュ後など）。Kindle を
  再起動してください。
- **KOReader が「Grimoire を起動できませんでした。grimoire/grimoire.log を参照してください。」と
  表示する**: 引き継ぎで Grimoire が起動していません。`grimoire/grimoire.log` の
  `grimoire.sh: not starting` の行に理由（KOReader がペンとタッチ画面をまだ手放していない、など）が
  あり、`already running` は別の Grimoire がまだ開いていたことを意味します。どちらもない場合は
  KOReader 内部で引き継ぎが失敗しています。KOReader 自身のログ `koreader/crash.log` に
  `Grimoire:` で始まる行があります。「この Grimoire は KOReader から開けません」は `documents` の
  `Grimoire.sh` が 1.1 より古いことを意味します。新しいものをコピーしてください。
- **ストロークがペン先からずれる**: **設定 > ペンとタッチのキャリブレーション**。そこへ行けない
  場合は、ライブラリの **Grimoire - reset pen calibration** をタップしてください。
- **画面が上下逆**（2022 の Scribe で起こり得ます）: `grimoire` フォルダに `screen-flip` または
  `screen-noflip` という空ファイルを置いて再起動します。
- **Kindle 自身の画面の一部が透けて見える**: Grimoire は自分で上から描き直します。繰り返す場合は、
  `grimoire` フォルダに `stop-framework` という空ファイルを置いてください。Grimoire の実行中は
  Kindle のインターフェースを完全に停止します（終了後に戻るまで数秒長くかかります）。KOReader から
  開いた場合はこのファイルは効果がありません。KOReader 自身が Kindle のインターフェースを一時停止
  しているためです。
- **Grimoire をタップしても何も起きない**: `grimoire/grimoire.log` を確認してください。不具合報告には
  必ず添付してください。

## バージョン間の移動

更新も 1 ファイル、戻すのも 1 ファイルです。1.1.0-beta.1 以降、Grimoire は新しいバージョンが書いた
理解できないデータ（インクデータ、新しい用紙、追加のページデータ、`settings.ini` や
`notebook.ini` の未知の行）を保持し、そのまま書き戻します。

- 完全に表示できないページは **読み取り専用** で開き、「このページは新しいバージョンで作られて
  います。読み取り専用で表示されます。」と表示されます。そのページでは書き込み、消去、クリア、
  用紙の変更が拒否されますが、削除はできます。編集するには Grimoire を更新してください。
- 新しいバージョンの用紙は **新しい用紙** という空白の用紙として表示され、そのページの用紙として
  残ります。その後に追加したページも同じ用紙になります。
- このバージョンにない新しい設定は、最も近い選択肢として動作し（3 状態のスイッチはオンかオフと
  みなされます）、その設定を変更するまでファイルに残ります。
- 95 バイト（アクセント付き文字で約 47 文字）を超えるノート名やフォルダ名は、アクセント付き文字の
  途中で切らずに収まるように短縮されます。

1.0.0-beta と 1.0.0-rc.1 はこれができません。新しいバージョンが書いた後にそこでノートを開くと
データが失われることがあります。新しい形式のページを `p<id>.qpg.damaged-<時刻>` として脇に
置いて空白で表示し（ページビューで見るだけでも起こります）、保存時に新しいデータを捨てます。
1.1.0-beta.1 以降は、ノートをもう一度開いたときにそのようなページを戻し、その間にページが
書き直されていれば両方のコピーを保持します。古いバージョンで削除したページは脇に置かれたまま
です。

**2 つの画面サイズの Scribe。** 2022 年と 2024 年の Scribe は 1860x2480 の画面、Scribe 3 と
Scribe Colorsoft はより大きな 1986x2648 の画面です。1.1 以降、ノートは作られたときのページ
サイズを保ちます。別サイズの Scribe では、ページは画面に合わせて表示され、書き込みは罫線に沿い、
新しいページ、PDF、PNG はノートのサイズになります。1.1 より前のノートは、ほとんどのページが
持つサイズを採用します。ペンとタッチのキャリブレーションは、別サイズの Scribe に `grimoire`
フォルダをコピーするとそれに従い、Grimoire が起動時に新しい画面に合わせて拡大縮小します。
1.1 より前のバージョンはすべてのページを自分の画面に引き伸ばし（サイズ差の 7%。書き込みが罫線から
ずれます）、そのページを変更すると保存します。1.1 に戻るとそのページはノートのサイズに戻り、
1.1 で書いた内容が罫線に戻ります（古いバージョンで追加したインクは同じ比率で移動します）。その
ため、別サイズの Scribe で古いバージョンに戻すと、そこで編集したすべてのページのインクが移動
します。

**言語。** 1.0.0-beta と 1.0.0-rc.1 は次に設定を保存したときに設定 > 言語の選択を忘れるため、
1.1 以降に戻ると言語は再び「自動」になります。

**KOReader。** 古いバージョンは KOReader の Grimoire プラグインをそのまま残します。KOReader の
Tools > Grimoire は残り、ノートの PDF とペンキャリブレーションのリセットも動作し、Grimoire を
開くは「この Grimoire は KOReader から開けません」と表示します。1.1 より古い `Grimoire.sh` は
KOReader から開けないためです。1.1 に戻れば Grimoire を開くは再び動作します。

**用紙としての画像。** 1.0.0-beta では、テンプレート、取り込んだページ、書き込んだページが
インクだけの空白用紙として表示されます。1.1 に戻れば、ノートを開いたときに画像が戻ります。古い
バージョンは白インクや正確な消しゴムを知らないため、消したインクが再び表示され、`settings.ini`
からピン留めペンも失われます。
